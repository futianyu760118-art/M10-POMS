# M10 ↔ M07 HLC 人事行政联调 V1.0

## 首条闭环：员工报修
1. M10 生成可授权的“报修申请”入口，员工输入设施位置/故障说明/可选照片。
2. 通过 M01 Policy/Guard 校验 actor、tenant、业务对象范围。
3. M07 创建 LogisticsRequest，返回专业单号与待办引用。
4. M07 行政专员接受工单、分派、处理、形成可复核结果。
5. 验收人核实，M07 结束专业流程；M02 记录 Event/Result/Evidence/Trace。
6. M10 读取经授权的 ResultRef，形成“过去的报告”。

## HLC 实际代码参考
- `src/pages/p-hrm/moduleConfig.ts`：职位、员工、入职、转正、异动、请假等现有资源配置。
- `backend-python/routes/org.py` 和 `services/org_structure.py`：组织、汇报关系与 tenant 过滤。
- `backend-python/services/hrm_module_catalog.py`：HR 模块/AI 能力目录。
- `backend-python/routes/auth.py`：旧身份机制，须经 M01 统一授权改造。
- `backend-python/routes/tasks.py`：**仅文件上传内存任务进度**，严禁当成持久化 WorkItem 服务。
- HLC 的实际报修 API/表、Outbox 和 M01/M02 服务端契约仍需源码/环境验证，不应虚构其已具备。
