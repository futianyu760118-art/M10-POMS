# spec-kit 落地流程（Claude Code + 小团队 0-1）

## 0. 前提

- Python 3.11+、Git、已装 `uv`
- 装 uv：`curl -LsSf https://astral.sh/uv/install.sh | sh`

## 1. 安装 CLI（每台机器一次）

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
specify --help
```

不想全局装，也可以用 `uvx --from git+https://github.com/github/spec-kit.git specify ...` 临时跑。

## 2. 在项目里初始化

```bash
cd <你的项目根目录>
specify init --here --integration claude --script sh
```

⚠️ **版本差异提醒（这条最容易踩）**：spec-kit 迭代很快，参数在不同版本间有变化——
- 旧版本文档写的是 `--ai claude`，该 flag 在 **0.10.0 已移除**，新版用 `--integration claude`
- 命令名也有 `/speckit.constitution`（点号）与 `/speckit-constitution`（连字符）两种写法

**以你实际安装的版本为准**：跑 `specify --help` 确认参数，在 Claude Code 里输入 `/speckit` 看自动补全出来的实际命令名。别照抄任何一篇教程。

初始化会写入：
- `.claude/skills/speckit-*/SKILL.md`（约 10 个技能）
- `.specify/`（模板、脚本、`memory/constitution.md` 占位）
- `specs/`（每个功能的产物目录）

## 3. 验证

```bash
specify check
```

然后进 Claude Code，输入 `/speckit` 看补全是否出现。

## 4. 提交什么

```bash
git add .specify/ specs/ .claude/skills/
git commit -m "chore: 接入 spec-kit"
```

**进 git**：`.specify/`、`specs/`、`.claude/skills/`（队友需要）
**忽略**：`.claude/settings.local.json`（本地个人配置）

> init 的输出可能提示把整个 agent 目录加进 .gitignore（因为可能存凭据）。**不要照做**——那样队友就拿不到 skill 了。只忽略 `settings.local.json` 这类本地文件。

## 5. 标准流程

轻量路径（小改动、探索性）：
```
/speckit.specify → /speckit.plan → /speckit.tasks → /speckit.implement
```

完整路径（生产功能、需求有歧义时，**0-1 建议默认走这条**）：
```
/speckit.constitution → /speckit.specify → /speckit.clarify → /speckit.checklist
→ /speckit.plan → /speckit.tasks → /speckit.analyze → /speckit.implement
```

各步骤职责：

| 步骤 | 产出 | 要点 |
|---|---|---|
| constitution | `.specify/memory/constitution.md` | **只写跨所有 feature 的全局原则**，不写具体需求 |
| specify | `spec.md` | 写**做什么和为什么**，不写技术栈 |
| clarify | 更新 spec.md | 最多 5 个澄清问题，可多次运行 |
| checklist | 需求质量报告 | 检查完整性/一致性 |
| plan | `plan.md` + 数据模型 + 契约 | 这里才给技术栈 |
| tasks | `tasks.md` | 粒度=一次有意义的 commit |
| analyze | 一致性报告 | 检查 spec/plan/tasks 是否自洽 |
| implement | 实际代码 | **新开一个 chat 跑**，避免前序上下文噪声 |

## 6. 与 CLAUDE.md 的分工

- **constitution** = 项目原则（全局、长期、很少变）
- **CLAUDE.md** = 日常操作约定（目录、命令、边界）
- 两者都进 git，都由团队评审维护

constitution 定好后，`/speckit.plan` 会用它做合规检查（如 Simplicity Gate、Test-First Gate）。**没有 constitution，这些检查就没有依据**——所以这一步不是走过场。
