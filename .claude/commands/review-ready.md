---
description: 提交 PR 前的自检，产出可直接粘贴的评审材料
---

准备提交当前改动。按下面做，**不要跳过任何一步**：

1. **看全量改动**
   - `git status` + `git diff`，逐个文件确认。
   - 列出**本次改动范围外的文件**（如果有，说明为什么动了它们，或回退）。

2. **跑校验**（原样粘贴命令与输出，不要只说"通过了"）
   - 类型检查、lint、测试。

3. **残留检查**
   - 临时调试代码、`console.log`、注释掉的代码块
   - 本次改动后不再被调用的旧函数/旧分支
   - 没有 TODO 指向具体任务

4. **对照规则自检**
   - 是否引入了白名单外的新依赖
   - 是否有"以防万一"式的抽象或兜底
   - 是否越过了模块依赖方向

5. **产出 PR 描述**，格式如下：

```
## 做了什么
<<改动文件 + 每个文件一句话>>

## 凭什么说完成
<<命令 + 实际输出>>
<<覆盖范围>>

## 已知风险 / 未覆盖
<<...>>

## 需要评审者重点看
<<...>>

## 我没动但注意到的
<<范围外的问题，只报告>>
```
