为下面这个需求开启新功能：$ARGUMENTS

按以下顺序推进，**每一步完成后停下来等我确认，不要一路跑到底**：

1. **复述需求**：用你自己的话说明要做什么、解决谁的什么问题。如果我理解错了，现在纠正成本最低。

2. **列出不清楚的地方**：把所有有歧义、需要我决策的点列成清单，一次问完。不要自己猜。

3. **给出最小实现范围**：明确这次做什么、明确不做什么（"不做"清单比"做"清单更重要）。

4. **确认技术选型**：涉及新依赖的，按 `.claude/rules/02-dependencies.md` 说明理由并等我批准。

5. **拆分任务**：拆到"一个 task 对应一次有意义 commit"的粒度。单个 task 描述超过 5 行就再拆。

6. **开始实现**：逐个 task 实现，每完成一个就汇报，跑测试，然后提交。

全程遵守：
- 反过度设计 → `.claude/rules/01-no-over-engineering.md`
- 交付证据 → `.claude/rules/03-delivery-evidence.md`
- 模块边界 → `.claude/rules/04-module-boundaries.md`
