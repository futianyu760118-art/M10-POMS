# 防跑偏（AEOS 7.2.2 基线对齐）

本团队确认的最大风险是**跑偏**——偏离 AEOS 7.2.2 红线与既有架构另搞一套。任何动手前先过三道闸，任何一道不过就停下说明，不得实现：

## 第一道闸：对照 AEOS 红线（CLAUDE.md「AEOS 7.2.2 红线」）

done≠verified / M10 不写专业库 / UI 隐藏≠权限 / 高风险人审 / 越权默认拒绝 409 / 候选状态诚实（mock 必须标注、未签批不称 Gate 通过）。

## 第二道闸：对照目录结构

新文件必须落在既有职责目录（apps / adapters / packages / configs / services / demo / tests / scripts）。**找不到归属就先问**，不许新建顶层目录，不许造 `xxxV2`、`newXxx`。

## 第三道闸：对照既有模式

- 新系统接入 = 复制 `scripts/import-from-plm.js` 导入模式 + 新建 `adapters/<系统>` + BFF `/api/v1` 路由
- 新页面 = 复用 demo 既有结构与门户登记，不自创框架/构建
- 新表格/列表 = 复用 `tblRender` 通用组件（搜索/筛选/排序/停用）

## 视为跑偏的信号（一律先报告不动手）

- 想做"第二套 XX 系统 / 主数据 / 状态机"（应引用，不复制）
- 想绕过 adapter 直连库或在 demo 里写业务状态机
- 想手编 `configs/plm2.json` 的真实业务数据（应跑导入脚本）
- 想在未跑 `npm test` 的情况下声称完成
- 需求与"岗位/采集/待办/审批/证据"主线无关且无用户明确指令
